# Каталог библиотечного фонда

Учебный модуль для курсовой работы: книги, авторы, физические экземпляры с состоянием, дарители и приёмка, поиск, сортировки и аналитика фонда. Хранилище — Microsoft SQL Server: таблицы, роли и права живут в базе, приложение ходит туда через ODBC. Консольное приложение на C++17 под Windows.

## Что умеет

- каталог книг: ID, название, несколько авторов, жанр, год издания, цена;
- экземпляры книг: инвентарный номер, состояние, кто принёс, кто из сотрудников принял, дата поступления;
- добавление книги сразу с нужным числом экземпляров; номера `INV-<id>-<n>` подбираются автоматически;
- редактирование книги: пустой ввод оставляет поле без изменений;
- удаление книги по ID или по точному названию;
- поиск по названию, автору и жанру без учёта регистра, фильтры по году и цене; при сортировке `ё` приравнивается к `е`;
- сортировки: год издания (возрастание/убывание), число экземпляров (возрастание), название, автор;
- аналитика: стоимость фонда с учётом состояния, книги к пополнению, топ-3 по цене, сводка по состояниям;
- вход по пользователю: роль и права загружаются из базы, меню строится по выданным правам;
- сохранение всего каталога в SQL Server одной транзакцией;
- локальный режим без SQL Server: работа в памяти с полными правами и сохранение, когда база станет доступна;
- автоматическая подготовка базы: при подключении создаётся БД и накатываются скрипты `sql/01–07`;
- перенос старых данных из таблицы `Books` (становится `Books_legacy`) и учебные демо-данные.

## Архитектура и слои

| Файл | Что делает |
|---|---|
| `include/Book.h` | доменные типы: `Book`, `BookCopy`, склейка списка авторов |
| `include/User.h` | пользователь: id, ФИО, логин, название роли |
| `include/Text.h` | UTF-8: `trim`, разбор списков, регистронезависимое сравнение и сортировка с `ё` |
| `include/Catalog.h`, `src/Catalog.cpp` | каталог в памяти: проверки, добавление/правка/удаление, экземпляры, поиск, сортировки, аналитика |
| `include/Condition.h`, `src/Condition.cpp` | состояния экземпляров как стратегии: коэффициент стоимости и доступность |
| `include/Console.h`, `src/Console.cpp` | консоль UTF-8, очистка экрана, меню со стрелками и цифрами |
| `include/Database.h`, `src/Database.cpp` | ODBC: подключение, создание БД, накат SQL-скриптов, чтение и запись каталога, пользователи и права |
| `main.cpp` | точка входа, вход в систему, меню и сценарии работы |

Использованы два простых приёма, без «магии»:

- **Стратегия** — каждое состояние экземпляра это отдельный класс `ConditionPolicy`. Единственная точка вариации — список в `ConditionRegistry::all()`. Остальной код о состояниях ничего не знает.
- **Слой данных** — `Database` описывает, что нужно приложению, а SQL Server реализует это через ODBC. Каталог (`Catalog`) не знает, куда сохраняется.

## Сборка

Нужен `g++` с заголовками ODBC (`sql.h`, `sqlext.h`) и библиотекой `odbc32`. Проверено на MinGW-w64 g++.

```bat
build.bat
```

`build.bat` сам ищет компилятор: сначала в `PATH`, затем в `C:\msys64\ucrt64\bin\g++.exe` и `C:\msys64\mingw64\bin\g++.exe`. Если g++ лежит в другом месте, поправьте поиск в начале файла. Сборка статическая, DLL рядом не нужны. Результат — `library.exe` в корне проекта.

Вручную:

```bat
g++ -std=c++17 -O2 -Wall -Wextra -finput-charset=UTF-8 -fexec-charset=UTF-8 -static -Iinclude -o library.exe main.cpp src/Console.cpp src/Catalog.cpp src/Condition.cpp src/Database.cpp -lodbc32
```

## Подготовка SQL Server

Нужны SQL Server 2019/2022 и драйвер ODBC Driver 17 for SQL Server (или 18). SSMS нужен только для ручного запуска скриптов: приложение умеет готовить базу само.

Порядок скриптов:

| Скрипт | Что делает |
|---|---|
| `sql/01_database.sql` | создаёт базу `Library`, если её нет |
| `sql/02_tables.sql` | таблицы, ключи, ограничения; старую `Books` переименовывает в `Books_legacy` |
| `sql/03_roles_permissions.sql` | роли `Администратор`, `Библиотекарь`, `Читатель` и права в `role_permissions` |
| `sql/04_users.sql` | учебные пользователи и их роли |
| `sql/05_conditions.sql` | справочник состояний: NEW, GOOD, WORN, BAD, LOST |
| `sql/06_legacy_migration.sql` | перенос книг, авторов и экземпляров из `Books_legacy` |
| `sql/07_demo_data.sql` | демо-данные, только если таблица книг пуста |

Все скрипты идемпотентны: повторный запуск безопасен. При старте приложение само открывает `db.ini`, подключается к `master`, создаёт базу при необходимости и выполняет `sql/01…07` по порядку, разбивая пакеты по `GO`. Файлы ищутся в папке `sql` рядом с `db.ini`, поэтому запускайте `library.exe` из корня проекта.

Через SSMS: откройте `sql/apply_all.sql` и включите режим SQLCMD (Query → SQLCMD Mode), затем Execute. Через `sqlcmd` кодировку задавайте явно, иначе кириллица в литералах испортится:

```bat
sqlcmd -S localhost -E -b -f 65001 -i sql\01_database.sql
sqlcmd -S localhost -E -b -f 65001 -i sql\02_tables.sql
sqlcmd -S localhost -E -b -f 65001 -i sql\03_roles_permissions.sql
sqlcmd -S localhost -E -b -f 65001 -i sql\04_users.sql
```

`apply_all.sql` программой не выполняется: у файла нет числового префикса.

## Настройка подключения

Параметры лежат в `db.ini` рядом с `library.exe`:

```ini
server=localhost
database=Library
trusted=yes
user=
password=
```

| Ключ | Значение |
|---|---|
| `server` | экземпляр SQL Server: `localhost`, `.\SQLEXPRESS`, `ИМЯ_ПК\SQLEXPRESS` |
| `database` | имя базы; только латинские буквы, цифры и `_`, по умолчанию `Library` |
| `trusted` | `yes` — вход Windows (`Trusted_Connection`), `no` — вход SQL-логином |
| `user`, `password` | логин и пароль SQL Server; нужны только при `trusted=no` |

Драйвер выбирается автоматически: ODBC Driver 18, затем 17, затем SQL Server Native Client 11.0, затем любой драйвер со «SQL Server» в имени. Для драйверов 17/18 приложение само добавляет `Encrypt=no;TrustServerCertificate=yes`, поэтому учебный локальный сервер работает без настройки шифрования. Таймаут подключения — 5 секунд.

Если соединения нет, приложение не падает: печатает причину и переходит в локальный режим. Каталог можно наполнить в памяти, а пункт «Сохранить изменения» подключится к базе заново.

## Роли и права

Паролей приложение не хранит: при старте показывается список пользователей из таблицы `users`, вы выбираете себя, а права читаются из `role_permissions` для роли этого пользователя. Это учебная имитация входа, а не проверка подлинности.

| Право | Что разрешает | Администратор | Библиотекарь | Читатель |
|---|---|---|---|---|
| `catalog.add` | добавлять книги и экземпляры | да | да | — |
| `catalog.edit` | редактировать книги | да | да | — |
| `catalog.delete` | удалять книги | да | — | — |
| `copies.manage` | экземпляры: добавить, изменить, удалить | да | да | — |
| `catalog.save` | сохранять каталог в SQL Server | да | да | — |
| `analytics.view` | аналитика фонда | да | да | — |

Пункты «Показать все книги», «Поиск и фильтрация», «Сортировка» и «Выход» доступны всем. Остальные пункты появляются в меню только при наличии права.

| Логин | ФИО | Роль |
|---|---|---|
| `admin` | Иванова Анна | Администратор |
| `librarian` | Петров Игорь | Библиотекарь |
| `librarian2` | Смирнова Ольга | Библиотекарь |
| `reader` | Кузнецов Павел | Читатель |

В локальном режиме (без SQL Server) выдаются все права, потому что роли взять неоткуда. В заголовке при этом написано «локальный режим, без ролей».

## Быстрый старт

```bat
build.bat
library.exe
```

1. Убедитесь, что SQL Server запущен и установлен драйвер ODBC Driver 17/18.
2. Проверьте `db.ini` (по умолчанию `localhost` / `Library` / вход Windows).
3. Запустите `library.exe` из корня проекта: программа сама создаст базу, таблицы и демо-данные.
4. Выберите пользователя в меню входа (например, `admin`).
5. Работайте в меню: стрелки — переход, Enter — выбор, цифра — сразу пункт, Esc — назад.

При первом запуске на пустой базе появятся 6 книг, 7 авторов, 4 дарителя и 10 экземпляров — это `07_demo_data.sql`.

## Меню

| Пункт | Что делает | Кому доступен |
|---|---|---|
| 1 | добавить книгу (можно сразу с экземплярами) | с `catalog.add` |
| 2 | редактировать книгу по ID | с `catalog.edit` |
| 3 | удалить книгу по ID или названию | с `catalog.delete` |
| 4 | показать все книги | всем |
| 5 | поиск и фильтрация | всем |
| 6 | сортировка каталога | всем |
| 7 | экземпляры книги: показать, добавить, изменить, удалить | с `copies.manage` |
| 8 | аналитика | с `analytics.view` |
| 9 | сохранить изменения в SQL Server | с `catalog.save` |
| 0 | выход (предложит сохранить несохранённое) | всем |

Из подменю можно выйти по Esc или пункту «Назад». Заголовок показывает пользователя, роль, адрес SQL Server и признак несохранённых изменений.

## Правила каталога

- Название: не пустое, до 255 символов. Жанр: не пустой, до 100 символов.
- Авторов от 1 до 10; пустые имена и повторы запрещены. Ввод — через запятую.
- Год издания больше 0, цена неотрицательная; ввод цены принимает `890`, `890.50`, `890,50`.
- ID книги задаётся вручную и должен быть целым; дубликаты запрещены.
- Инвентарный номер: не пустой, до 30 символов, уникален по всему каталогу без учёта регистра.
- Дата поступления хранится строкой `ГГГГ-ММ-ДД`; при добавлении подставляется сегодняшняя.
- При создании экземпляров подряд номера берутся из `INV-<id книги>-<номер>` и пропускают занятые.
- При редактировании пустой ввод означает «оставить как было», а Enter на списке авторов сохраняет прежний список.

Состояния экземпляра:

| Код | Название | Коэффициент стоимости | Доступен для выдачи |
|---|---|---|---|
| `NEW` | Новое | 1.00 | да |
| `GOOD` | Хорошее | 0.85 | да |
| `WORN` | Потёртое | 0.60 | да |
| `BAD` | Ветхое | 0.30 | да |
| `LOST` | Утеряно | 0.00 | нет |

Стоимость фонда — сумма `цена книги × коэффициент состояния` по всем экземплярам. «Книги к пополнению» — те, у кого доступных экземпляров (все, кроме `LOST`) два или меньше. «Топ-3» — по цене книги.

## Схема базы

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `roles` | роли | `name` уникально |
| `role_permissions` | права роли | `role_id`, `permission`, первичный ключ из двух полей, каскадное удаление |
| `users` | пользователи | `full_name`, `login` уникален, `role_id` |
| `authors` | авторы | `full_name` уникально |
| `books` | книги | `id`, `title`, `genre`, `year`, `price DECIMAL(12,2)` |
| `book_authors` | связь книг и авторов | `book_id`, `author_id`, `author_order` |
| `conditions` | состояния | `code`, `title`, `value_factor`, `available_for_loan` |
| `donors` | дарители | `full_name` уникально, `contact` |
| `book_copies` | экземпляры | `inventory` первичный ключ, `book_id`, `condition_code`, `donor_id`, `received_by`, `received_on` |
| `Books_legacy` | старая таблица книг до разделения на авторов и экземпляры | появляется только при миграции |

Ограничения: каскадное удаление связей книга–автор и экземпляров вместе с книгой, уникальность названия роли, логина, имени автора, дарителя, инвентарного номера и пары «роль + право».

Сохранение выполняется одной транзакцией и заменяет содержимое фонда: строки `book_copies`, `book_authors`, `books` и `donors` удаляются, затем вставляются книги, связи, экземпляры и дарители из текущего каталога. Авторы добавляются по имени и не удаляются, роли, права и пользователи не затрагиваются. Контакты дарителей приложение не редактирует, поэтому после сохранения `donors.contact` остаётся пустым; дарители, не привязанные ни к одному экземпляру, из таблицы исчезают.

## Как добавить новое состояние экземпляра

1. `src/Condition.cpp` — новый класс-наследник `ConditionPolicy` (код, название, коэффициент, доступность) и `static` экземпляр.
2. Там же — добавьте его в список `ConditionRegistry::all()`.
3. `sql/05_conditions.sql` — строка в `VALUES` с тем же кодом, названием, коэффициентом и признаком доступности.
4. Проверки, меню состояния, стоимость фонда и сводка подхватят новое состояние сами: они берут данные из реестра.

## Как добавить новое право

1. `main.cpp` — константа вида `catalog.export` и условие `can(permissions, ...)` для нового пункта меню.
2. `sql/03_roles_permissions.sql` — строка `(N'Роль', N'catalog.export')` в `VALUES`.
3. Перезапустите приложение: права читаются при входе, на ходу они не обновляются.

## Разбор частых ошибок

| Сообщение / симптом | Причина и что делать |
|---|---|
| `Не найден компилятор g++` | установите MSYS2 UCRT64 или добавьте g++ в `PATH` |
| `Не найден драйвер ODBC для SQL Server` | установите ODBC Driver 17/18 for SQL Server (64-бит) |
| `Нет соединения с SQL Server (...)` | сервер не запущен, неверный `server` в `db.ini`, выключен TCP/IP |
| `Имя базы в db.ini может содержать...` | в `database` только латиница, цифры и `_` |
| `Не найдена папка SQL-скриптов` | запускайте `library.exe` из корня проекта, рядом с `db.ini` и `sql/` |
| `Ошибка в 02_tables.sql: ...` | проверьте права учётной записи на создание таблиц в базе |
| `Не удалось загрузить права роли` | выполните `03_roles_permissions.sql`; до этого доступен только просмотр |
| «Учётной записи нет в списке» | выполните `04_users.sql` или добавьте пользователя в таблицу `users` |
| Кириллица ромбиками | запускайте в Windows Terminal; приложение само включает UTF-8 |
| Кириллица испорчена после `sqlcmd` | запускайте скрипты с `-f 65001` или через SSMS |
| «Соединение есть, но прочитать каталог не удалось» | не накатились таблицы; посмотрите текст ошибки ODBC и выполните `02_tables.sql` вручную |
| «Сохранение заменит содержимое таблиц» | при старте каталог не загружался; подтвердите, если это ожидаемо |

## Ограничения учебного проекта

Однопользовательская работа: нет конкурентного редактирования и блокировок. Вход — выбор пользователя из списка, пароли не проверяются. Нет выдачи и возврата книг, читательских билетов, истории движений фонда. Сохранение заменяет каталог целиком, поэтому параллельные правки из разных окон затрут друг друга. Цена хранится как `double` в приложении и `DECIMAL(12,2)` в базе. Этого достаточно для курсовой, но недостаточно для промышленной эксплуатации.
